# 設計書: カードの動きを見せる（「ためしてみる」）

作成: 2026-07-26（Chat）／ 状態: **神田さんの判断待ち（★印）**
発端: 実機FB「各カードの説明はOKですが、実際の動きのアニメーションがポップアップなどで合わせて表示されるといいのですが」

---

## §0. なぜ必要か

カードは29種。`desc`（せつめい文）は全種に付いているが、**文だけでは動きが伝わらない**ものが多い。

- 「くりかえし」＝ 中に入れたカードを、決めた回数ぶん くりかえすよ → **入れ子の概念が文で伝わるか**
- 「はねかえる」＝ かべに ぶつかると はねかえるよ → **どう跳ねるか**
- 「とべるように」＝ したに おちるように なって、▲で とべる → **重力という新概念**

低学年は文字を読むこと自体が負荷になる。**動きを1秒見せる方が速い。**

---

## §1. ★現状の制約（Chat が実装を確認）

| | 現状 |
|---|---|
| 表示場所 | ながおしのふきだし `.palDesc` |
| 大きさ | **max-width 250px**・padding 10×13 |
| 中身 | `long`（正式名）＋ `desc`（せつめい）＋「そのまま ひっぱると おけるよ」 |
| **表示時間** | **指を押している間だけ**。離すと `clearPalPending()` で消える |
| 操作 | **`pointer-events: none`** ＝ ふきだし自体は触れない |

### 1-1. ここが設計を縛る

**「押している間だけ」ではアニメを見られない。** 1〜2秒のループを見るために指を押し続けるのは、低学年にはつらい。しかも指がカードの上にあるので、**ふきだしが指で隠れる**。

**触れないので「もう一回」も押せない。**

⚠️ **ながおし → せつめい → ドラッグの三段導線は、教育的な理由で設計されたもの**（`parallel-design.md` の落とし穴「触れただけで確定するUIにしない」）。**壊さないこと。**

## §2. ★設計案（3つ・Chat の推奨は案B）

### 案A: ふきだしの中でループ再生

いまのふきだしに小さなアニメ領域（220×90程度）を足し、押している間ループ再生。

- ○ 追加の操作がゼロ。導線を1ミリも変えない
- ✕ **押し続けないと見られない**。指でふきだしが隠れる
- ✕ 250px幅にアニメ＋文を詰めると窮屈

### 案B: ふきだしに「ためしてみる」ボタン ★推奨

ふきだしの下に**ボタンを1つ**足す。押すと**画面中央に大きめのパネル**が開き、その中でアニメがループする。「とじる」で閉じる。

- ○ **指を離しても見られる**。何度でも見返せる
- ○ 中央の大きな枠なので、**動きがはっきり見える**（400×260程度）
- ○ ながおし → せつめい → ドラッグの三段導線は**そのまま**。ボタンは「四段目の任意の枝」
- ✕ `.palDesc` の `pointer-events: none` を外す必要がある（ふきだしが触れるようになる）
- ✕ **ドラッグとの競合**に注意（下記 2-1）

### 案C: せつめいふきだしを「タップで開く」方式に変える

ながおしで開いたふきだしを、指を離しても残す。

- ○ アニメも文もゆっくり読める
- ✕ **三段導線の意味が変わる**。b5x で実機OKをもらった操作を作り直すことになる
- ✕ 閉じる操作が要る＝低学年に手数が増える

## §3. 案B の詳細（推奨案）

### 3-1. ★ドラッグとの競合（最重要）

いま `.palDesc` は `pointer-events: none`。これを外すと、**ふきだしの上を通ったドラッグが吸われる**恐れがある。

- **ボタンだけ `pointer-events: auto`** にし、ふきだし本体は `none` のまま
- ボタンは**ふきだしの下端**に置く（カードから遠い側）。指はカードの上にあるので、そこへ届くには一度離す動きが要る＝誤爆しにくい
- ⚠️ **b5z で直した「指ドラッグが無言で消える」不具合の周辺**。実装後、**棚の全カテゴリから指でドラッグできることを必ず再確認**する

### 3-2. パネルの仕様

- 画面中央・**400×260程度**（iPad で見やすく、PCでも大きすぎない）
- 中身: **アニメ領域**（上）＋ `long`（正式名）＋ `desc`＋「とじる」
- **ループ再生**。1周 1.5〜2秒
- 閉じ方: 「とじる」ボタン ＋ **外側タップ**
- 開いている間は**背後を暗く**（既存の確認ダイアログと同じ作法）

### 3-3. ★アニメの作り方（29種をどう表現するか）

**画像や動画を29本用意するのは非現実的。** 生成コストも保守コストも高い。

**推奨: いまのステージ描画をそのまま小さく使う。**

エディタには既に **12×8のステージ＋キャラを動かす仕組み**がある（`CharSprite`・`cellPx`・`--hopH` 等）。これを**縮小した「ミニステージ」**としてパネル内に置き、**そのカードだけを実行する**。

- ○ **新しい絵を1枚も作らない**
- ○ **本物と同じ動き**が見える（別に作ったアニメだと本物とズレる危険がある）
- ○ カードが増えても**自動的に対応する**（`clone` を足しても何もしなくていい）
- ✕ エンジンを小さく回す仕組みが要る

⚠️ **エンジンは凍結ベースライン（トレース732イベント）に直結する。** ミニステージ用に**エンジンを改造しない**こと。既存の `createEngine` をそのまま使い、小さな台本を与えて回すだけにする。**動かないなら案を変える**（下記 3-4）。

### 3-4. 代替: 「まえ／あと」の2コマ

3-3 が難しい場合の逃げ道。**動く前と動いた後**を2コマで見せ、矢印でつなぐ。

- ○ 実装が軽い（ステージの静止画を2枚描くだけ）
- ○ 「みぎへ」「おおきく」「きえる」などは十分伝わる
- ✕ 「くりかえし」「ずっと」「はねかえる」は2コマでは伝わらない

**組み合わせも可**: 単純なカードは2コマ、動きが要るカードだけミニステージ。ただし**2つの仕組みを保守することになる**ので、できれば一本化したい。

### 3-5. カードごとの台本

29種それぞれに「何を見せるか」の短い台本が要る。データとして持つ形（例）:

```
みぎへ      → キャラ1体。中央から右へ3マス動く
くりかえし   → キャラ1体。くりかえし×3〔みぎへ〕を実行。カウンタも見せる
はねかえる   → キャラ1体。右端まで行って跳ね返る
ぶつかったら  → キャラ2体。ぶつかって片方が大きくなる
じゅうじキー  → キャラ1体＋十字キーの絵。押されて動く様子
とべるように  → キャラ1体。落ちて着地し、跳ぶ
```

**この台本は Chat が29種ぶん書く。** 神田さんの承認後に。

## §5. 実装の順序（案B・ミニステージの場合）

便を3つに割るのが安全。**一度に作ると、ドラッグ競合とエンジン周りの問題が同時に出て切り分けられない。**

| 便 | 内容 | 実機で見るもの |
|---|---|---|
| **①** | ふきだしにボタン ＋ 空のパネルが開閉するだけ | **指ドラッグが壊れていないか**（最重要）・ボタンが押しやすいか |
| **②** | ミニステージで1種類だけ動く（「みぎへ」） | 動きが見えるか・大きさは適切か |
| **③** | 残りの台本を流し込む | 各カードの動きが伝わるか |

①で**ドラッグ競合が出たら、そこで止めて設計に戻る**。b5z の不具合を再燃させるのが最悪。
