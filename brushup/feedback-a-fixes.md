## §1. ピルのはみ出し（原因特定済み）

### 1-1. 原因

`.studio-root .pill` に `box-sizing` の指定が無く、既定の **`content-box`**。
CSS の `min-width: 32px` は**内容だけ**に効き、そこへ `padding: 1px 11px`（左右計22px）が足されて**実寸54px**になる。
一方 `cardW()`（`StudioBlock.jsx`）は
`pillW = Math.max(32, 文字幅 + 22)` ＝ **42px** と見積もっている。**12px不足**。
短いピル（`×3`）でのみ起きる。`だれか` のような長いピルは文字幅が32を超えるので一致する。

### 1-2. 直し方

**`.studio-root .pill` に `box-sizing: border-box` を足す**（1行）。

- はみ出しが直る（実寸が42pxになり `cardW` の見積もりと一致）
- **同時に「余白が大きい」も解消**（54→42px）。神田さんが挙げた2案のうち「小さくする」側で、カードを広げずに済む
- 長いピルは変化しない

⚠️ `cardW()` の式は**変えないこと**。式が正しく、CSS 側がずれていた。

## §2. きっかけカードの接続ずれ（原因特定済み）

### 2-1. 原因

`StudioBlock.jsx` の `<svg>` で、**要素の高さと `viewBox` の高さが食い違っている**。
ブラウザは既定の `preserveAspectRatio="xMidYMid meet"` により**小さい方の倍率で全体を縮小し、横中央に寄せる**。

```
svg width={w + 2} height={hh + G.TD + 4}
viewBox={`-1 ${isHat ? -4 : -1} ${w + 2} ${hh + G.TD + (isHat ? 9 : 6)}`}
```

| | 要素の高さ | viewBox の高さ | 縦倍率 | 幅190pxのカードの左端のずれ |
|---|---|---|---|---|
| **きっかけ**（HATH=56） | 68 | **73** | 93.2% | **右へ 6.6px** |
| ふつう（H=48） | 60 | **62** | 96.8% | 右へ 3.1px |

**症状と一致する**: きっかけの方が食い違いが大きく、しかも**カードが広いほどずれる**。
`はた`（約96px）は3.4pxでほぼ見えず、`ぶつかったら だれか`（約190px）は6.6pxで目立つ。

### 2-2. 直し方

**`viewBox` の高さを要素の高さに一致させる**（横は既に `w+2` で一致している）。
上方向の余白（`isHat ? -4 : -1`）は**きっかけの上ふくらみ（y=-2）を切らないために必要**なので、`height` 側を viewBox に合わせるか、viewBox の高さを縮めるかは Code が判断してよい。**判断と理由を報告すること。**

条件: **上のふくらみも下のツメ（TD=8）も切れないこと**。

### 2-3. ⚠️ 副作用（想定内・報告すること）

いま作業エリアのカードは意図せず 93〜97% に縮小されている。直すと**100%で描かれる＝カードが3〜7%大きくなる**。

- これは**正しい状態への復帰**であり、退行ではない
- とくに**きっかけとふつうのカードの相対サイズが揃う**（いまきっかけだけ3.6%小さく描かれており、それ自体がずれの一部）
- **こうぐだな（棚）は別描画**（`WorkshopEditor.jsx` L1537 に独自の svg・`PAL_S` で意図的に縮小）なので、**b6a で実機調整した棚の大きさには影響しない**。Chat が確認済み
- 実機で作業エリアのカードが大きすぎると感じたら、`CANVAS_S`（現在 0.86）1つで調整できる。**本便では変えない**

## §3. 落ちものキャッチの判定漏れ（原因特定済み）

### 3-1. 原因

**ぶつかり判定が「拍」の中でしか評価されていない**（`engine.js` の `tick` 内・`overlapNow()` と `prevOverlap` の比較）。
拍は 400ms、じゅうじキーの移動は `OP_MS = 100ms`。

```
拍0      リンゴ(5,3) 主人公(5,2)   重なりなし
+100ms   主人公が(5,3)へ ← 同じマス。だが判定は走らない
拍1      リンゴが(5,2)へ落ちる → 判定：重なりなし
```

**すれ違っても取れない。**

### 3-2. 直し方

**操作ループ由来の移動のあとにも、同じ重なり判定を走らせる**（じゅうじキー・タップいどう・重力）。

⚠️ **判定の実装は1つに保つこと**（拍の中と操作ループで別々に書かない）。`prevOverlap` の状態も1つ。二重に書くと発火が重複する。

### 3-3. ★ここが本便で最も慎重を要する

エンジンに触るため、**凍結トレースが動く危険がある**。

- studio のみほん4本は**操作ループを一切通らない**（`dpad` / `tapMove` / `jumpable` は gamelab 専用）。よって**トレース732イベントは1バイトも動かないはず**
- **動いたら手を止めて報告**。`--update` は実行しない
- 拍の中の既存の判定順序（`bump` → `bumpTarget` → `goal`）を**組み替えないこと**

## §4. こうぐだなの並び（★gamelab のみ）

### 4-1. やること

`GAMELAB_PALORDER` の せいぎょ を **`くりかえし` → `ずっと` → `まつ`** の順にする。
2列に流し込む仕組みなので、この順にすれば **くりかえし｜ずっと が横並び、その下に まつ** になる。

**この並びは場所の使い方としても良い**: くりかえし・ずっとは容器（背が高い）、まつは背が低い。いまは `まつ｜くりかえし` が同じ行にあるため、まつの隣に無駄な高さが生まれている。

### 4-2. ⚠️ studio の `PALORDER` は絶対に触らない

回帰ハーネスは `blocks.palorder`（studio 18種）が**基準の先頭からの部分列であること**を要求する（**末尾追加のみ許容**）。
**並べ替えると FAIL する。**
studio 側も同じ並びにしたい場合はベースラインの再取得が必要で、「studio 完全無変化」の原則に関わる。**本便では扱わない**（神田さんの指摘は gamelab の画面についてのもの）。

## §5. キャラの大きさ（★gamelab のみ）

### 5-1. 現状

`CFG.ACTOR_K = 2.2` ＝ キャラ表示幅 = `cellPx × 2.2`。盤は12マスなので**画面幅の18.3%**。

### 5-2. やること

**`ACTOR_K` を gamelab のときだけ 1.8 にする**（画面幅の15.0%）。`WorkshopEditor.jsx` の `actorBase` を計算する箇所には `mode` があるので、`mode.isGame` で分岐できる。

- **studio は 2.2 のまま**（`ACTOR_K` は共有・studio は「見せる作品」でキャラが主役。実機OK済みの見た目を変えない）
- 副次効果として、**隣のマスのキャラとの視覚的な重なりが減る**（2.2 だと隣接マスでも絵が重なって「触れているように見える」）。§3 の判定と見た目の一致が良くなる

### 5-3. 値は実機で調整できるようにする

**1.8 は Chat の見立て。** 実機で合わなければ**この1つの定数だけ**を変えて再調整する（大きすぎ→1.6／小さすぎ→2.0 が目安）。
定数にコメントで「実機の手触りで調整する値」と明記すること。
