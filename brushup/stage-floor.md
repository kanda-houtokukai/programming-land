## §1. なぜ床にするか（判断の記録）

### 1-1. 事実（Chat が独立に検算済み）

⚠️ **数値は 2026-07-26 に Code が再実測して差し替えた**（初版の「上から32.9%」は誤り。32.9% だと空にかかるのが2行になり、下の「3行」と矛盾する）。**結論は初版のまま変わらない。**

| | 実測（幅420〜720px） | iPad実寸（幅570px） |
|---|---|---|
| そうげんの地平線 | theater の**上から 42.2%**（下から57.8%） | 同左 |
| **マス目が占める高さ** | theater の高さの **84〜91%** | 88.4% |
| 上に空く余地 | **32px 固定＝7〜11%** | 8.4% |
| **立てない行** | **y=5〜7 の3行** | 3行 |

測り方: 背景は 1600×900（16:9）を 3:2 の theater へ `object-fit: cover` するので**横だけが切られ、縦の比率はそのまま**＝画像の地平線の縦位置がそのまま theater の縦位置になる。

**y=5・6・7 の3行が地平線より上**にある。そこにキャラが立つと**空に浮く**。じゅうじキーで実際にそこまで動ける。

### 1-2. 当初案（案あ「上1/3を遠景＋下2/3に床」）が成立しない理由

上に空いているのが **32px（7〜11%）**しかないため、遠景の帯を作っても**マス目が2〜3行食い込む**。問題が解決しない。

Chat が案あを推奨したが、**マス目が高さの9割を占めることを計算していなかった**。取り下げる。

### 1-3. スタジオとゲームで要求が違う

- **スタジオの背景＝書き割り（見るもの）。** 遠近があってよい
- **ゲームの背景＝読むもの。** 「どこに立てるか」を絵が答えなければならない

いまの絵はそこで嘘をついている。神田さんの「目的が異なる」はこの区別。

## §2. ★スタジオをどうするか（着手前に確認して報告）

**Chat が調べた事実**: `.bgimg`（ステージの背景画像）は `WorkshopEditor.jsx:1897` の**1箇所だけ**で、**studio と gamelab の分岐がない**。`BGS`（`studio-bgs.js`）も共有。

つまり**素直に実装すると、スタジオの背景も床になる。**

**方針（Chat の判断）**: **gamelab だけ床にする。studio は従来の絵のまま。**

理由:
- §1-3 のとおり、スタジオは「書き割り」でよい。**あの絵はスタジオでは正しく機能している**
- 「そらに立つ」問題は**じゅうじキーで自由に動けるゲーム**で顕在化する。スタジオは1拍ずつの演出で、上段へ行くのは作り手の意図
- スタジオは b6u まで実機OK。**変える理由がない**

`mode.isGame` で分岐すること（`.studio-root.gl` のスコープ制御と同じ作法）。

⚠️ **この判断に異論があれば、実装前に報告すること。** 「両方床にする」も選択肢ではある（統一感は増すが、スタジオの世界観が失われる）。

### 2-1. 確認結果（Code・2026-07-26）＝ **異論なし。ただし対象が1ファイル増える**

§2 の事実はすべて裏づけ済み（`.bgimg` は 244行のCSSと 1897行の描画の2箇所のみ・分岐なし／`mode.isGame` は gamelab のみ true で studio 側はキー自体が無く falsy 確定）。判断にも異論なし。

**追加の裏づけ**: studio は `ACTOR_K = 2.2` で gamelab の 1.8 より大きい＝上端は studio のほうが厳しい。studio を触らない方針は §4（B-2）のリスクも同時に下げる。

★ **ただし「背景画像を描く場所」は `.bgimg` の他に3つある**:

| 場所 | 影響 |
|---|---|
| `.bgthumb` ぶたい選択（`WorkshopEditor.jsx:2042`） | §3-1 が明記済み |
| みほんのたな（`WorkshopHome.jsx:247`） | **影響なし** ── gamelab のみほんは全10種に `cover` 絵があり `StudioThumb` を通らない |
| **作品サムネ（`StudioThumb.jsx:22`）** | ★**カセットだなのサムネだけ絵のまま**になる |

`StudioThumb({ bg, chars, width, profile })` は **`mode` を受け取っておらず** studio と gamelab で共用。使われるのは `WorkshopHome.jsx:209`（かきかけ）と `:225`（カセットだな／フィルムだな）。このままだと**カセットだなに絵のサムネが並び、開くと床**＝§3-1 が禁じた食い違いそのもの。

**判断（神田さん・2026-07-26）**: **StudioThumb も本便に含める。** `WorkshopHome` は既に `mode` を持っているので `isGame` を渡し、gamelab の作品サムネだけ床にする。**studio のサムネは従来の絵のまま。**

⚠️ **一致は「気をつける」ではなく構造で保証する** ── 床の見た目は `studio-bgs.js` の `floorStyle()` 1関数に集約し、**ステージ・ぶたい選択・作品サムネの3箇所すべてがそれを呼ぶ**。id と色の対応が3箇所でずれる余地を作らない（§6 の「id と色の対応」検証はこの前提で行う）。

## §3. 床の仕様

### 3-1. 5種の床（ぶたい名・id・ショップ商品はすべて維持）

| id | 名前 | 床の色（案・調整可） | 由来 |
|---|---|---|---|
| `sougen` | そうげん | 明るい黄緑 | 草原 |
| `jungle` | ジャングル | 深い緑 | 密林 |
| `canyon` | だいち | 赤茶 | 岩肌 |
| `arena` | アリーナ | 砂色 | 闘技場の土 |
| `studio` | スタジオ | 木の色（暖かい茶） | 舞台の床 |

- **名前・id・ショップの商品（`bg_jungle` / `bg_canyon`・各100コイン）は1文字も変えない**
- ショップの表示（サムネ）は**従来の絵のまま**でよい。買うものは「ぶたい」であって絵ではない
- ⚠️ **ぶたい選択の `.bgthumb`（エディタ内）は床の見た目に合わせる**こと。選んだ結果と違う絵が並んでいると混乱する

### 3-2. うっすらマス目

**「ためしてみる」で承認済みの表現をそのまま広げる**（`WorkshopEditor.jsx:147` の `.palDesc .anim` と同じ考え方）。12×8 が分かる程度の薄い線。

### 3-3. ★物を置かない

**岩・花・木などの「物」を描かないこと。** ぶつかり判定のあるゲームでは**障害物に見える**。

床の表情は**色と、ごく薄い模様**（縞・格子・微細なテクスチャ）まで。

これがスタジオと要求が違う点。スタジオの背景に花や岩があるのは、そこが「見るもの」だから。

### 3-4. 画像を作らない・差し替えない

**CSS の色と模様だけ**で作る。`bg_battle_*.webp` には一切触らない。

バトルの絵はバトルで生き続ける（案あの狙いだった「資産を捨てない」は、絵に触らないので完全に達成される）。

## §4. 監査B-2（キャラの頭がはみ出す）を同じ便で片付ける

### 4-1. 事実

`cellPx = min((幅−52)/12, (高さ−44)/8)` と、キャラ高さ `cellPx × ACTOR_K` が釣り合っていない。

**y=7（最上段）のキャラが上端で切れる。** 監査の計算では **47px はみ出す**。

**b6u の実機では未発生**（通し確認で✅）だが、**式としては成立している**。ステージの高さ配分が変わると再燃する。

### 4-2. 直し方

**床を敷く実装でステージの描画に触るので、ここで一緒に見る。**

- 上端の余白（現在 `44/2 = 22px`）を、`ACTOR_K` を考慮した値にする
- または y=7 のキャラが収まるようマス目の配置を調整する
- ⚠️ **`G.SNAP = 78`・保存座標・`cellPx` の式そのもの**は変えないこと。凍結ずみの手触りに直結する
- **studio 側の見え方が変わらないこと**を確認する（`ACTOR_K` が 2.2 で gamelab の 1.8 より大きいため、studio の方が厳しい）

**手を入れると実機で見え方が変わるので、変更前後を実測して報告**すること。

## §5. 変えないもの

- **ぶたいの名前・id・ショップの商品と価格**
- `bg_battle_*.webp` などの画像ファイル（**1バイトも触らない**）
- **studio のステージ背景**（§2 の判断）
- `G.SNAP = 78`・保存座標・`cellPx` の式・`CFG.MOVE_MS`・`OP_MS`・`TICK`
- `ACTOR_K = 2.2`（studio）／`ACTOR_K_GAME = 1.8`（gamelab）
- **エンジン・`DEFS`・`geometry.js`・凍結ベースライン**
- ぶたいのショップ連動（b6m）・カードの動き見本19種（b6u）
- `SCHEMA_VERSION`（9のまま。**保存データは増えない**）
