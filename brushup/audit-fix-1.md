## §1. A-1 かんとくベレーが永久に入手できない

### 1-1. 事実（Chat 検証済み）

`src/data/dressup.js` の解放判定:

```js
studio_all_cards: save => {
  const used = usedBlockTypesInWorks((save.studio && save.studio.works) || []);
  return Object.keys(STUDIO_DEFS).every(t => used.has(t));   // ← STUDIO_DEFS = DEFS 全29種
},
```

- `Object.keys(STUDIO_DEFS)` ＝ **DEFS 全29種**を要求
- しかし studio の `PALORDER` は **18種**。差の11種は**すべて gamelab 専用**で studio の作品に置けない
  → `bounce` `bumpTarget` `chase` `dpad` `fall` `goal` `jumpable` `moveRand` `scoreDown` `scoreUp` `tapMove`
- 判定は `save.studio.works` だけを見るので、gamelab の作品では埋まらない

**＝ どうやっても達成できない。** ラベルは「つくるスタジオで **18しゅるい**の カードを ぜんぶ つかうと もらえる」、flavor も「**18まい**の カードを つかいこなした」のまま。**ラベルが元の仕様を示している。**

`DEFS` が 18→20 になった時点（段階1で `scoreUp`/`scoreDown` 追加）から壊れている。ショップでも買えないので回復手段がない。

### 1-2. 直し方

**判定を studio の棚（`PALORDER` の18種）に限定する。**

```js
return PALORDER.every(t => used.has(t));
```

ラベルの「18しゅるい」が元の意図なので、**ラベルに合わせて判定を直すのが正しい**（逆にラベルを29に直すのは不可能な条件を掲げることになる）。

### 1-3. ★同じ事故を防ぐ仕組みを足す

この不具合は **`npm run verify` が全PASSしても検出できなかった**。テストは通り、UIも正常に見え、子どもが達成できないだけだった。**同じ形の再発を機械で止める。**

`npm run verify` に次の照合を追加すること（`gen-cards --check` と同じ考え方）:

- **`studio_all_cards` が要求する型数と、ラベル／flavor に書かれた数字が一致すること**
- 一致しなければ FAIL

これで、将来 `PALORDER` に種類が増えたときにラベルの更新漏れが即座に分かる。

**実装が難しい／verify が不安定になる場合は、組み込まずに報告**すること（その場合は判定のすぐ上にコメントで警告を残す）。

### 1-4. 影響

既に studio で18種すべてを使っている子は、**修正後すぐに解放される**（正しい挙動）。`checkAchievementUnlocks` がいつ呼ばれるかを確認し、**次の保存や画面遷移で拾われること**を確かめて報告すること。

## §2. B-1 キャラを消して保存すると相手指定がすり替わる

### 2-1. 事実（Chat 検証済み）

| 場所 | 何が起きるか |
|---|---|
| `WorkshopEditor.jsx` 保存（`doSaveWork`） | `chars.map(c => ({ kind, x, y, stacks }))` ＝ **`cid` を捨てる** |
| `WorkshopEditor.jsx` 読み込み（`loadScene`） | `cid: "c" + (i + 1)` ＝ **配列順で振り直す** |
| `studio-blocks-defs.js` `cloneBlocks` | `{ ...b }` ＝ **`target: "c3"` は文字列のまま残る** |
| `engine.js` `fireTargetTrigger` | `tgt === "any" \|\| tgt === other.key` ＝ **存在しない cid には永久に一致しない** |

**途中のキャラを消して保存 → 開き直すと、的が外れる。**

さらに悪いことに、b6d で入れた `targetName` の救済（消えた cid は「だれか」と表示）が、**この不具合を隠している**。
**ピルは「だれか」と出るのに、エンジンは一度も発火しない。** `gameOver.targetId` も同じで、ばくだんが「◯」のまま誰にも💀が付かず、**負けが成立しないゲーム**になる。

`target` を使うのは `bumpTarget` / `goal` / `gameOver.targetId` の3つ。**`chase` だけは b6d で救済済み**（消えた指定は最も近いキャラを追う）で、3枚のうち1枚だけ作法が違っていた。

### 2-2. 直し方（★方針は Chat が決めた）

**(1) 保存時に `cid` を残す。**
`doSaveWork` の `chars.map` に `cid` を含める。これが根治。キャラを消しても残りの cid は変わらず、的が外れない。

**(2) 読み込み時、`cid` があればそれを使う。無ければ従来どおり配列順で振る。**

```
cid: c.cid || ("c" + (i + 1))
```

⚠️ **無い場合の挙動を1バイトも変えないこと。** みほんのデータには `cid` が無いため、**変えるとエンジンのトレース732イベントが動く**（`other.key` が cid 由来）。ここは凍結ベースラインに直結する。

**(3) `cidSeq`（新しいキャラに振る番号）が既存と衝突しないようにする。**
いまは `chars.length` を起点にしている箇所がある。`cid` を持つ作品を読んだ場合、**既存の最大値+1** から振ること。衝突すると別のキャラが同じ cid を持ち、事態が悪化する。

**(4) 古い保存作品の救済。**
`cid` を持たない既存作品は、開いた時点で的が外れている可能性がある。読み込み後に**解決できない `target` を検出**し、次のように落とす:

- `bumpTarget` / `goal` の `target` → **`"any"`**（＝ピルの「だれか」表示と挙動が一致する）
- `gameOver.targetId` が解決できない → **`gameOver = null`**（ばくだんを切る）

理由: いまは「表示は正常なのに動かない」が最悪の形。**表示と挙動を一致させる**のが子どもにとって正直。`gameOver` を `"any"` にすると「誰に触っても負け」という別物になるため、切る側に倒す。

**この救済の判断に異論があれば、実装前に報告すること。**

### 2-3. スキーマと試験

保存の形が変わるので:

- **`SCHEMA_VERSION` を 9 に上げる**
- `tools/test-roundtrip.mjs` に追加:
  - `cid` を持つ作品の**往復で `cid` が保たれる**
  - `cid` を持たない旧作品が**従来どおり `c1..cN` になる**
  - **途中のキャラを消して保存 → 読み込みで `target` が保たれる**（この不具合の再発検知）
  - 解決できない `target` が §2-2(4) のとおり落ちる

`CLAUDE.md` の「セーブ項目を増やしたら往復試験に足す」に従う。
