## §A. マップに建物を置く

### A-1. 置き場所 【確定】

現在マップには**じゅんびちゅう看板が2枚**ある。これは「ここに何か建つ」という予告の飾りで、タップできない。**この片方をこうぼうの建物に差し替える**のが、設計正本の言う「看板→建物」。

| 候補 | 座標 | スタジオ(59.5, 12.4)からの距離 | 所感 |
|---|---|---|---|
| **看板① 右寄り** | 69.5, 34.13 | 23.9 | マップ右側。バトル(88,26)寄り |
| **看板② 中央上** | 47.3, 29.25 | 20.8 | マップ中央。タイピング(47,51)の真上 |

**Chat の推奨は「看板①（69.5, 34.13）」。** 理由:

- **こうぼうは「遊ぶものを作る」場所**で、バトル（88, 26）と近い位置にあると「遊ぶ島の側」という意味づけが立つ。中央はタイピング・おうちに囲まれた生活動線で、性格が違う
- 看板②は**マップのど真ん中**で、既存エリアに四方を囲まれている。新しい建物を置くと**視線がそこに集中して、マップ全体の重心が崩れる**
- 看板①を消しても、看板②が残るので「まだ増える」という予告は維持できる

**ただし最終判断は神田さんの実機で。** 座標の微調整は `studio-map-placement.md` の換算規約に従う:
**dx = r·sin(θ) / dy = −r·cos(θ)**（θ＝12時から時計回り・1時=30°・単位は%ポイント）

### A-2. 表示の仕様（既存規約に準拠・Chat が実測して確認済み）

| 項目 | 値 | 根拠 |
|---|---|---|
| `tall` | **true**（82%表示） | 建物はほぼ正方形だが、スタジオも同条件で実機承認済み |
| 縦の余白 | **上0・下0** | 既存4棟すべてこの規約。**余白を付けるとマップ上で約7%小さく表示される**（スタジオ開店時に一度発生し修正された不具合） |
| 左右反転 | **不要** | 光源を実測: こうぼう **+11.7＝左光源**。既存（quiz +5.3 / home +18.6 / typing +41.8 / studio +1.0）と一致。スタジオは反転が必要だったが、こちらは元から揃っている |
| `short` / `place` | **「ゲーム」/「ゲームこうぼう」** | 下記 A-3 |

### A-3. 名前 【確定】

マップの名前は3階層で役割が分かれている（`short`＝短縮ラベル／`place`＝場所名／画面タイトル＝各画面が持つ）。

問題は、**スタジオの `short` が「つくる」**であること。こうぼうも「作る」場所なので、素直に付けると子どもが区別できない。

| 案 | `short` | `place` | 所感 |
|---|---|---|---|
| **あ（推奨）** | **ゲーム** | **ゲームこうぼう** | 「つくる（スタジオ）」と「ゲーム（こうぼう）」＝**何を作るかで分かれる**。低学年に一番通じる |
| い | こうぼう | ゲームこうぼう | 「こうぼう」は低学年に難しい語。ひらがなでも意味が取れない |
| う | あそぶ | ゲームこうぼう | 「作る」性格が消える。バトルやパズルと混同する |

**推奨は案あ。** 既存の `short` はすべて2〜5文字（クイズ／おえかき／ちから／おみせ／おうち／タイピング／パズル／バトル／みなと／つくる）で、「ゲーム」は3文字で収まる。

### A-4. 開放条件 【確定】

現在、開放条件があるのは**バトルだけ**（`areaLocked = a => a.key === "battle" && !battleOk`）。スタジオには制限がない。

**Chat の推奨は「制限なし」。** 理由:
- こうぼうはスタジオの姉妹モードで、**作ることに前提条件を付けない**のがこのアプリの姿勢（スタジオも無制限）
- レベル制限を掛けると「まだ使えない建物」がマップに増える。灰色の建物は子どもには「壊れている」ように見える
- 難しさで自然に選別される（こうぼうはスタジオより概念が多い）ので、機構で塞ぐ必要がない

## §D. 教育接続 【確定】

現在 `src/gamelab/works.js` の `grantForNewSave` は**常に `null`**（コメントに「教育接続の付与は段階3で載せる」と明記）。**こうぼうで作品を保存しても、XPもコインも記録も一切増えない**。

### D-1. スタジオの既存ルール（そのまま参考にできる）

- **XP**: `XP.studioSave() = 10`。**新規作品の初回保存のみ**（作り直しでは出ない）
- **コイン**: マイルストーン初達成時のみ。`first:15 / works5:20 / works10:30 / firstNest:15 / firstCast3:15`
- **きろく**: `profile.log[日付].studio` を新規保存のみカウント
- **空作品ガード**: `sceneNonEmpty` でキャラの無い作品は対象外

### D-2. こうぼう版の提案

XPは**同額（10）**を推奨。作る労力は同等で、モードによって差を付けると「得な方だけやる」誘因になる。

マイルストーンは**こうぼう固有のものを立てる**。スタジオのそのまま流用では、こうぼうで学ぶことを拾えない。

| id | 条件 | コイン | 何を拾うか |
|---|---|---|---|
| `first` | 初めて1本作った | 15 | 最初の一歩 |
| `works5` | 5本作った | 20 | 続けた |
| `works10` | 10本作った | 30 | 続けた |
| `firstOperable` | **じゅうじキー か タップいどう を使った** | 15 | **人が操作するものを作った**＝こうぼう固有 |
| `firstClear` | **クリア条件を「なし」以外にした** | 15 | **勝ち負けを設計した**＝こうぼう固有 |

⚠️ **`firstNest`（容器の中の容器）と `firstCast3`（キャラ3体）はスタジオ側の id と重複する。** マイルストーンは `studio.milestones` に保存されているので、**こうぼうは `gamelab.milestones` に別で持つ**こと（混ざるとスタジオの達成がこうぼうにも効いてしまう）。

### D-3. 「作らせすぎ」への配慮

正本の教育思想に「コインはやりすぎを示すサインにならない設計（上限なし）」とある。上の表もマイルストーン方式で、**同じことを繰り返してもコインは増えない**。この原則は維持している。

## §E. おうちのひとへ（保護者ガイド）【確定】

`src/gamelab/mode.jsx` は `guide: null` で、**こうぼうには保護者ガイドが無い**。ホーム側に `{guide && …}` のガードがあるので、いまは項目自体が出ない。

スタジオは `STUDIO_GUIDE`（`src/data/parent-guide.js`）を持ち、`title: "この しまで そだつ ちから"` ＋ `body` の配列という形。同じ形で `GAMELAB_GUIDE` を書く。

**書く内容の骨子（案）**:
1. **ここは何をする場所か** — ブロックを組んで「遊べるゲーム」を作り、その場で遊べる
2. **スタジオとの違い** — スタジオは「見せる作品」、こうぼうは「遊ぶ作品」。同じブロックで目的が変わる
3. **育つ力** — 順次・繰り返し・条件分岐に加えて、**「遊ぶ人のことを考えて作る」**という設計の視点
4. **見守りのヒント** — 「うまく動かない」ときが学びの本番。答えを教えず「どうしたい？」と聞く
5. **制御は教育的理由で存在する** — 既存ガイドの原則を踏襲

**文面は本書では書かない。** ガイドは分量があり、既存ガイドとの語調の統一が要るので、**判断が固まってから単独で作る**。

## §F. 進め方の提案

**アセットの配置と、機能の追加は分けるべき。** 素材差し替えは見た目の確認で済むが、教育接続は付与ルールが絡んで検証の性質が違う。

| 便 | 内容 | 実機で見るもの |
|---|---|---|
| **① 素材差し替え** | §B（アイコン11枚・建物・内観） | 棚のアイコンが揃った・内観が変わった |
| **② マップ開店** | §A（建物配置・看板削除・名前・導線） | マップから入れる・座標の微調整 |
| **③ 教育接続** | §D（XP・コイン・きろく・マイルストーン） | 保存でXPとコインが出る |
| **④ ガイド＋BGM** | §E・§C | ガイドが読める・音が鳴る |

①は Code が戻ればすぐ出せる。②は①の建物が入っていないと確認できないので、この順。
