## §0. なぜやるか（背景・読むだけ）

`progland-handoff.md`（台帳）が **76,059文字**まで肥大した。`CLAUDE.md` の規約により**全セッションが起動時にこれを読む**ため、Code が1行も書かないうちにコンテキストの 20〜30% を消費している。実際、直前のセッションは便①ひとつで 90% に達した。

伸び方:

```
2026-07-21  55,864文字
2026-07-22  58,694文字
2026-07-23  64,729文字
2026-07-24  76,059文字  ← いま
```

内訳を見ると **「今どこか」セクションだけで 67,481文字＝台帳の89%**。版ごとの記録が **55版ぶん**積み上がっている。b4e（7/12）のような、とっくに出荷済みで参照されない版まで毎回読まれている。

**古い版の記録を別ファイルへ移し、台帳は「いま効いていること」だけにする。**

---

## §1. ★重要: 台帳を全文読み込まずに処理する

この作業自体でコンテキストを使い切っては本末転倒。**行操作で処理すること。**
`view` で全文を開かない。境界の数行だけ確認して、あとは `sed` 等で切り出す。

### 1-1. 境界の確認（数行だけ読む）

Chat が HEAD `2dcacb7` 時点で実測した境界は次のとおり。**まずこの4箇所だけ表示して、想定と合っているか確認する。**

| 行 | あるべき内容 |
|---|---|
| **L115** | b6g エントリの最終行（`⚠️次: 神田さんの実機確認…` で終わる） |
| **L116** | `- **v2.3-b5w（2026-07-21・ゲームこうぼう段階2…` ← **ここから移す** |
| **L391** | `- ⚠️次:神田さんの実機確認（3箇所のアイコンの大きさ…` ← **ここまで移す** |
| **L392** | `- 検証体制: \`npm run verify\` ＝ パズル162面…` ← **これは残す** |

**ズレていたら手を止めて報告。** 行番号を推測で進めない。

### 1-2. 切り分け

- **移す**: L116〜L391（**b5w 〜 b4e ＝ 55版中45版**・49,129文字）
- **残す**: L1〜L115（ヘッダ・現在地サマリ・次にやること・開店フェーズ確定事項・**b5x〜b6g の10版**）＋ L392〜末尾（検証体制・未完了タスク・次の一手・ファイルの地図・決定事項・生きている注意事項・教訓）

**結果: 台帳 76,059 → 約 26,930文字（35%）。**

### 1-3. 手順（順序を守る)

1. `sed -n '116,391p'` で切り出して新ファイルへ
2. **切り出した内容の行数・文字数が想定と合うか確認**
3. `sed -i '116,391d'` で台帳から削除（**必ず切り出しの後**。先に消すと行番号がずれる）
4. 台帳の残りが約 26,930文字になったか確認

## §3. ★再肥大を防ぐ規則を入れる（これが本題）

**分離しただけでは2週間で元に戻る。** 規則を明文化すること。

### 3-1. 台帳に規則を書く

台帳の適切な位置（「ファイルの地図」か冒頭付近）に、次の趣旨を記載する:

```
版エントリは直近10版まで。11版目を足すときは、最も古い1版を
progland-archive-YYYY-MM.md へ移してから追記する。
台帳が3万文字を超えたら、この規則が守られていない。
```

### 3-2. `CLAUDE.md` にも1行足す

`CLAUDE.md` は全セッションが読む。**台帳の維持規則がここにないと、次のセッションが知らずに追記して肥大する。**
「台帳に版を追記するときは直近10版に保つ（超過分はアーカイブへ）」の趣旨を1行加える。

### 3-3. アーカイブのファイル名

月ごとに分ける（`progland-archive-2026-07.md` / `-08.md` …）。1本に積み続けると、いずれアーカイブ自体が扱いにくくなる。

## §4. 移す前に確認すること（★内容の救出）

アーカイブへ移す45版の中に、**いまも効いている制約**が埋もれていないか確認する。埋もれていたら、**台帳の「生きている注意事項」か「決定事項」へ昇格**させてから移す。

特に次のような性質のものは、版の記録ではなく**現在の仕様**なので台帳に残すべき:

- 数値の確定値（寸法・しきい値・定数など）
- 「◯◯してはいけない」という禁則
- 失敗して学んだ落とし穴

**チェック方法**: 移す範囲（L116〜L391）を切り出したあと、その中を `grep` で拾う。全文を読む必要はない。

```
確定 / 禁止 / してはいけない / 落とし穴 / 教訓 / ★
```

拾った候補のうち**いま効いているものだけ**を台帳へ昇格させ、**判断と根拠を報告**すること。
迷ったら残す側に倒してよい（消えるより重複する方が安全）。

## §5. あわせて確認: 古い「⚠️実機確認待ち」は誤解を招く

アーカイブへ移す45版には、**b5k 以前に `⚠️実機確認待ち` のまま残っているもの**が多数ある。これらは 7/12〜7/21 の版で、**その後の版に置き換わって出荷済み**。実際に待っている作業ではない。

移すことでこの誤った「未完了」表示が台帳から消える。**これは副作用ではなく狙い**。

ただし、**本当に未消化のものが紛れていないか**だけ確認して報告すること（`未完了タスク` セクションと突き合わせる）。
